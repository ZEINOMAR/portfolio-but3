Objectif du projet

Implémenter de zéro le Yalta, variante des échecs à trois joueurs sur un plateau hexagonal de 96 cases, avec un moteur de règles rigoureux, une IA jouable et une interface graphique soignée, en respectant une architecture orientée objet propre.

Technologies utilisées

  • Java 21, Maven
  • JavaFX (controls, graphics) et javafx-maven-plugin
  • JUnit 5 — 121 tests répartis sur 8 classes (plateau, topologie, génération de coups, détection d'échec, commandes, évaluation…)
  • Programmation concurrente : ExecutorService, Future, thread daemon

Le plateau hexagonal

Le plateau est un hexagone découpé en six quadrilatères de 4 × 4 cases ; chaque joueur possède deux quadrilatères adjacents. Au centre, les lignes et diagonales changent de secteur : la classe BoardTopology encode ces voisinages et BoardGeometry calcule les polygones affichés. Un système de coordonnées continu (1 à 12) permet de repérer chaque case.

Intelligence artificielle

L'IA utilise une recherche alpha-bêta paranoïaque : à trois joueurs, elle suppose que les deux adversaires cherchent à minimiser son score. Les coups racine sont ordonnés puis évalués en parallèle sur un pool de threads, avec une profondeur de 3 et une limite de 3 secondes. Le calcul tourne dans un thread daemon et le résultat est renvoyé à l'interface via Platform.runLater, ce qui garde l'UI fluide.

int nThreads = Math.min(rootMoves.size(), Runtime.getRuntime().availableProcessors());
ExecutorService executor = Executors.newFixedThreadPool(nThreads);

for (Move move : rootMoves) {
    futures.add(executor.submit(() -> {
        Board copy = board.copy();
        copy.move(move);
        return alphaBeta(copy, MAX_DEPTH - 1, Integer.MIN_VALUE, Integer.MAX_VALUE,
                aiPlayer, aiPlayer.next());
    }));
}

L'évaluation est injectée via le pattern Strategy :

public interface EvaluationStrategy {
    /** Évalue le plateau du point de vue de forPlayer. */
    int evaluate(Board board, PlayerColor forPlayer);
}

mvn clean javafx:run   # lancer le jeu

Problématiques rencontrées & solutions

  • Géométrie non standard (directions qui changent au centre) → table de topologie dédiée plutôt que des calculs de coordonnées cartésiennes.
  • Minimax classique pensé pour 2 joueurs → variante paranoïaque de l'alpha-bêta adaptée à 3 joueurs.
  • Interface figée pendant le calcul de l'IA → thread daemon + Platform.runLater, et recherche parallélisée avec limite de temps.
  • Historique et annulation des coups → pattern Command : chaque coup est encapsulé dans un objet exécutable et annulable.
  • Fin de partie à 3 joueurs → gestion de l'élimination : les pièces du joueur maté sont retirées et la partie continue.
