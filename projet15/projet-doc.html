Objectif du projet

Développer un réseau social pour les étudiants du CERI : connexion, mur de publications, likes, commentaires, partages et notifications en temps réel, le tout dans une application monopage performante et responsive.

Technologies utilisées

DonnéesPostgreSQL (pg) pour les utilisateurs, MongoDB (driver natif / mongoose) pour les posts et sessions

Architecture

Le serveur Express sert à la fois l'API REST et le build de production Angular (fichiers statiques), ce qui permet un déploiement sur un seul port HTTPS. Les comptes utilisateurs restent dans la base relationnelle existante, tandis que le contenu social, fortement évolutif, est stocké sous forme de documents.

Temps réel

Chaque action importante est diffusée à tous les clients connectés. Extrait réel de la route de like : la mise à jour est atomique côté MongoDB, puis l'événement est émis à tous les clients via Socket.io.

const update = alreadyLiked
  ? { $pull: { likedBy: userId }, $inc: { likes: -1 } }
  : { $addToSet: { likedBy: userId }, $inc: { likes: 1 } };

const updated = await collection.findOneAndUpdate(
  { _id: searchId }, update, { returnDocument: 'after' }
);

io.emit('likeUpdated', {
  postId: req.params.id,
  likes: updated.likes,
  likedBy: updated.likedBy
});

Problématiques rencontrées & solutions

  • Identifiants MongoDB hétérogènes (ObjectId et numériques) → résolution des identifiants et utilisation du driver natif MongoDB.
  • Likes concurrents et doublons → opérations atomiques $addToSet / $pull avec $inc.
  • Chargement du mur trop lourd → pagination offset / limit et scroll infini côté Angular.
  • Utilisateurs dans PostgreSQL, contenu dans MongoDB → résolution des pseudos à la lecture des posts et commentaires.
  • Synchronisation entre navigateurs → diffusion Socket.io des connexions, likes et partages.
